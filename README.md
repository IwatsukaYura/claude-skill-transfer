# Claude Code ガードレール研修

**目的** — Skills / Subagent / rules / Hooks が実際にガードレールとしてどう効くのかを、
ある状態と無い状態を並べて体感してもらい、その上で自分たちで作れるようになってもらう。

対象は Claude Code を日常的に使っているエンジニア。基本操作の説明はしない。

---

## この研修の主張

> **Claude はリポジトリの中にあることは自力で見つける。**
> **ガードレールに書く価値があるのは、リポジトリの中に無いことだけ。**
> **そして「守ってほしい」を「守らせる」に変えられるのは Hooks だけ。**

そして測って分かったもう一つの事実:

> **Claude は驚くほど安全側に寄っている。危険な操作は自分から確認してくる。**
> **だからガードレールは「Claude の暴走を止める装置」ではない。**
> **リポジトリに無い事実を実行時に持ち込み、正しい道に乗せる装置。**

これは推測ではない。本リポジトリの `demo/` で実際に測った結果である
（[02-体感デモ台本.md](02-体感デモ台本.md) に全計測値を掲載）。

素の Claude Code と rules を入れた Claude Code に同じ実装を依頼したところ、
**差が出たのは「リポジトリのどこにも書かれていない事実」1点だけ**だった。
所有権チェックもテストも監査ログもドキュメント更新も、ガードレール無しで正しく行われた。

だからこの研修は「ガードレールを増やそう」とは言わない。
**どこに書けば効くのか、どこに書いても無駄なのかを、測って判断できるようになる**ことを目指す。

## 実演環境

| ディレクトリ | 役割 |
|---|---|
| `demo/` | 実演用のリポジトリ。**Claude に見せる世界はここだけ** |
| `guardrails/` | ガードレールの実体。`demo/` の外に置いてある |
| `guardrails.sh` | ガードレールを1枚ずつ着脱する |

`guardrails/` を `demo/` の外に置いているのは意図的。
中に置くと、ガードレールOFFのときでも Claude がソースを読んで自主的に従ってしまい、
**「無い状態」が再現できなくなる**（実際に一度これで計測を失敗した）。

### 準備（研修の前日までに）

```bash
./setup.sh
```

ネットワークが必要なのはここだけ。当日はオフラインでも回る。
`node` `npm` `git` `jq` `claude` が必要。

### 当日の操作

```bash
./guardrails.sh status
```

```bash
./guardrails.sh off
```

```bash
./guardrails.sh only rules
```

| レイヤー | 中身 |
|---|---|
| `claudemd` | CLAUDE.md |
| `rules` | `paths:` スコープ付き rules |
| `skill` | `release-check` スキル |
| `agent` | `diff-reviewer` サブエージェント |
| `hook-migrations` | PreToolUse: 適用済みマイグレーションの書き換えをブロック ★デモ4の主役 |
| `hook-tests` | PreToolUse: テストの削除・skip をブロック |
| `hook-lint` | PostToolUse: 編集後チェックを Claude に返す ★デモ4の主役 |
| `hook-testgate` | Stop: テストが通るまで終わらせない |
| `hook-worktree` | PreToolUse: 未コミットの作業を破棄する git 操作をブロック（付録） |
| `hook-secrets` | PreToolUse: 秘密情報ファイルへの書き込みをブロック（付録） |
| `hook-trace` | InstructionsLoaded: どの指示ファイルがいつ・なぜロードされたか記録（**rules の診断用**） |
| `hooks` / `all` | フック7種まとめて / 全部 |

**`only` と `on` の違い**: `on` は**加算的**（`on skill` の後に `on rules` で両方有効になる）。
デモの切り替えでは **`only` を使う**。`only` は毎回 off してから有効化する。

**切り替えたら Claude Code を起動し直すこと。** 設定はセッション開始時に読まれる。

デモは必ず `demo/` をカレントにして起動する。

```bash
cd demo && claude
```

## 講師向けの注意

- **`guardrails.sh` は講師個人の `~/.claude/CLAUDE.md` と `~/.claude/rules/` を自動的に除外する。**
  これが混ざると「ガードレール無し」の状態が再現しない。
  `demo/.claude/settings.local.json` に `claudeMdExcludes` が書き出される。
  外したいときは `GUARDRAILS_NO_ISOLATE=1` を付ける
- 参加者の個人スキル（`~/.claude/skills/`）は除外できない。
  デモ2の前に `/context` で何が載っているか全員に見せて、差異があることを共有しておく
- **デモの結果は毎回同じにはならない。** 台本の実測値は「こうなった」の記録であって保証ではない。
  ズレたらそれ自体を教材にする（「同じ入力でも揺れる。だから決定論的に止めたいなら hook だ」）
- **台本には HTML コメントで「講師向けの注意」が埋め込まれている。**
  デモ3とデモ4には、作成中に実測で否定された仮説とその経緯が書いてある。
  当日反証されるリスクを避けるため、必ず先に読むこと
