  - [ ] どこにも無い（人の頭の中だけ） → **必ず書く**

## 記入例

## FR-012 リリース前チェックを毎回手で指示している

- **観測**: 週3回、同じ5ステップを貼り付けている。3人が同じことをしている
- **この情報はどこにある?**: リポジトリの別の場所（`scripts/` にあるが誰も参照していない）
- **コードで表現できないか?**: `npm run release-check` にまとめることはできる。
  ただし「結果をどう報告するか」「NGのとき何を見るか」はコードにできない → skill も要る
- **診断**: Skill。手順であって事実ではない。副作用は無いので自動発火を許可する
- **お願いで足りるか**: 足りる。実行し忘れても事故にはならない（CIで止まる）
- **検証方法**: skill 有り／無しで同じプロンプトを新規セッションで3回ずつ流し、
  ① 5項目すべてが実行されるか ② 出力形式が毎回同じか を数える
- **担当 / 状態**: @xxx / 完了（合格率 3/3 → 3/3、形式の一致 0/3 → 3/3）

## 運用ルール

1. **「検証方法」が空欄の項目は着手しない。** 埋まらないなら問題が言語化できていない
2. **週次で棚卸しする。** スタンドアップに5分枠を作るのが現実的
3. **「無しでも守られた」は成果。** 作らずに閉じてよい。むしろ良い
4. **四半期に1回、既存のガードレールを剪定する。**
   `/doctor` と `/usage` を見て、使われていないものを消す

## 健全性の指標

- 起票数と消化数（落ちたらループが止まっている）
- `.claude/` 配下のファイル数と、**削除数**（増える一方なら剪定が回っていない）
- `#claude-code` チャンネルの**講師以外の回答率**
